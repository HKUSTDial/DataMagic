# Rendering DVSpec — A Reference Path Using Remotion

DVSpec is **renderer-agnostic** (see `dvspec.md`). This file shows **one** way to compile it into
a video — a Remotion composition — chosen because code-first composition is the most natural fit
for coding agents. The mapping ideas here (scene → component, semantic data binding,
narration-indexed triggers, audio-driven duration) carry over to other stacks: charts via
D3 / Vega-Lite / ECharts, animation via GSAP / Anime.js. Only the rendering API changes; the
DVSpec and the planning rules do not.

For generic Remotion mechanics — `interpolate`, `spring`, `Sequence`, `Series`, `Audio`,
`calculateMetadata`, fonts, easing — defer to the `remotion-best-practices` skill. This file
covers only the **data-video-specific** structure.

## Project shape

```
src/
  Root.tsx                 # registers the <Composition>
  DataVideo.tsx            # top-level: renders scenes in order
  scenes/
    OpeningScene.tsx
    ChartScene.tsx
    StatCardsScene.tsx
    NarrativeCardScene.tsx
    ClosingScene.tsx
  charts/                  # data-bound chart components (you generate these)
    BarChart.tsx
    LineChart.tsx
    ...
  data/
    dvspec.json            # the plan
    <dataset>.json         # the source data
public/
  voiceover/<scene-id>-<segment-index>.mp3  # one per narration segment, generated by voiceover.md
```

**One DVSpec scene → one React scene component.** The DVSpec `scenes` array maps directly to a sequence of components.

## Mapping rules

### Scene sequence → `<Series>` (or `<Sequence>`)

Render scenes back-to-back, each occupying frames sized to its narration audio (see `voiceover.md` for how duration is derived). Use Remotion's `<Series>` so each scene's duration is declared once and offsets are computed automatically.

```tsx
<Series>
  {dvspec.scenes.map((scene) => (
    <Series.Sequence key={scene.id} durationInFrames={sceneDurations[scene.id]}>
      <SceneRouter scene={scene} />
    </Series.Sequence>
  ))}
</Series>
```

`SceneRouter` switches on `scene.type` and renders the matching scene component.

### `scene.type` → component

| DVSpec `type` | Component | Notes |
|---|---|---|
| `opening` | `OpeningScene` | headline + subtitle, animated in |
| `chart` | `ChartScene` | routes on `content.chart_type` to a chart component |
| `stat_cards` | `StatCardsScene` | 2–4 animated number cards |
| `narrative_card` | `NarrativeCardScene` | routes on `content.card_type` (see scene-planning.md) |
| `closing` | `ClosingScene` | summary statement, calm outro |

### `content.chart_type` → chart component

Generate one data-bound chart component per type you use. Each reads `content.data`, `content.data_binding`, and the scene palette. Keep them **data-driven** — never hardcode values.

```tsx
// ChartScene.tsx
const chartByType = {
  bar_chart: BarChart,
  line_chart: LineChart,
  pie_chart: PieChart,
  scatter_chart: ScatterChart,
  // ... only the types you actually use
};

export const ChartScene: React.FC<{ scene: Scene }> = ({ scene }) => {
  const Chart = chartByType[scene.content.chart_type];
  return (
    <ChartFrame title={scene.content.title}>
      <Chart
        data={scene.content.data}
        binding={scene.content.data_binding}
        highlight={scene.content.highlight}
      />
    </ChartFrame>
  );
};
```

> For the mechanics of animating bars/lines (entrance staggers, value count-ups, axis draw-on), read `remotion-best-practices` → `rules/charts.md` and `rules/animations.md`. This skill tells you *which* chart and *what* to emphasize; that skill tells you *how* to animate it in Remotion.

#### Chart-craft defaults (what makes a chart look finished)

- **Headroom:** set the value axis max to `dataMax × 1.2` so value labels and the highlight callout have room above the tallest mark.
- **Rounded marks:** bars get `borderRadius`/`rx` of **6–8px**. Full-width bars (band padding ~0.2) — never thin bars.
- **Soft depth:** one subtle drop shadow on marks (`drop-shadow(0 4px 6px rgba(0,0,0,0.3))`). Use a real drop-shadow, not a blurry glow on everything.
- **Highlight fill:** the highlighted bar/slice can use a subtle vertical gradient (`highlight → accent`); all others use one flat series color.
- **Gridlines:** thin, **behind** the marks, low opacity (`surfaceBorder`). Never draw gridlines over bars.
- **Numbers:** format compactly (`1.2K`, `3.4M`) with tabular figures; value labels sit ≥18px above the bar, weight 700.
- **Selective labels:** with 5+ marks, label only the highlighted one(s); axes carry the rest (see `design-system.md` content discipline).

## Data binding discipline

The whole point of a *data* video is provenance: every visual mark traces to a data record.

- Chart components must read values from `content.data` via `content.data_binding` keys. Do **not** inline literal numbers in JSX.
- Column names are **case-sensitive** and must match the source data exactly.
- If the data changes, only `content.data` changes — the component code stays the same.

## Animation: narration-indexed triggers → frames

DVSpec animations use `trigger` = the **index of a narration segment**, not a frame number (see `dvspec.md`). At compile time, convert each trigger to a frame using the per-segment audio durations from TTS:

```tsx
const triggerFrame =
  scene.animation[i].trigger == null
    ? 0
    : narrationSegmentStartFrames[scene.animation[i].trigger];
```

Resolve `target_data` (e.g. `{ "Category": "Software" }`) by matching records in `content.data` — **never** a hardcoded index. This keeps the animation correct even if data reorders.

### Highlight animation — the most important effect

A `highlight` does **three things together** when `frame >= triggerFrame`:

1. **Dim non-highlighted marks to ~0.45** (not lower) over ~12 frames — they stay readable as context.
2. **Emphasize the highlighted mark** with the **warm highlight color** (`#ff6b6b` / `#ef4444`, never a series color) + a **glow** + a **calm pulse** (1.0–1.03×). Pulse, do not scale big.
3. **Show a callout annotation** — a floating badge with the called-out value (e.g. `"$182K · +25% YoY"`) that springs in.

```tsx
const { fps } = useVideoConfig();
const hlFrame = getAnimationFrame(hlAnim?.trigger ?? null);
const hlStarted = frame >= hlFrame;

// Calm pulse — subtle breathing, NOT a big scale jump
const t = Math.max(0, (frame - hlFrame) / fps);
const pulse = hlStarted ? Math.sin(t * Math.PI * 4) * 0.03 + 1 : 1; // 1.00–1.03×

// Dim others to 0.45 (keep context readable)
const dimOpacity = hlStarted
  ? interpolate(frame, [hlFrame, hlFrame + 12], [1, 0.45], { extrapolateRight: "clamp" })
  : 1;

// Per mark:
const opacity = isHighlighted(d) ? 1 : dimOpacity;
const scale   = isHighlighted(d) ? pulse : 1;
const fill    = isHighlighted(d) ? theme.color.highlight : theme.color.series[i];
const glow    = isHighlighted(d) && hlStarted
  ? "drop-shadow(0 0 12px rgba(255,107,107,0.55))" : "none"; // SVG filter; box-shadow for HTML
```

> **Where the highlight target comes from:** decide which mark(s) to emphasize by reading the **highlight animation's `target_data`** — this is the narration-driven source of truth. A scene-level `content.highlight` is only an *optional static* emphasis (highlighted from frame 0). Don't depend on `content.highlight` being set; resolve the animation's `target_data` the same way for every chart type, or bar charts will highlight and line charts won't.

> **Multiple simultaneous highlights** (narration says "Minneapolis *and* Dallas"): collect **all** active highlight targets into a `Set` first, then style every mark in one pass. If you apply highlights one animation at a time in a loop, the last one overwrites the others and only one shows. Also: when emphasis ends, **restore** marks to their normal state (full opacity, no stroke) or they stay stuck dim.

### Entrance animations — concrete timing (time-based, `easeCubicOut`)

Drive chart entrances by **elapsed seconds**, not frame ratios, with `easeCubicOut`:

| Mark | Stagger | Duration | Notes |
|---|---|---|---|
| **Bars** | 0.12s per bar | 0.6s | Grow from baseline (animate both `height` and `y`) |
| **Value labels** | follow their bar | 0.4s, +0.3s after bar | Fade in just behind the bar |
| **Scatter dots** | 0.08s per dot | 0.5s | Grow radius + fade together |
| **Line** | — | 0.6s, starts at 0.2s | `stroke-dashoffset: PATH_LENGTH → 0` |
| **stat_cards** | ~0.3s per card | spring | Count value up with `easeCubicOut`, not linear |

Do **not** grow all bars at once from frame 0 (reads static). For line charts, draw lower-value series first and the primary series last, so it reads "…and Software pulled ahead."

## Theme

`meta.mode` (`light` | `dark` | `balanced`) sets the global palette. Define a theme object once and thread it to every scene; do not let individual scenes invent unrelated colors. Keep a single visual identity across the whole video (one background family, one type scale).

## Build order (recommended)

1. Scaffold `Root.tsx` + `DataVideo.tsx` with hardcoded placeholder durations — get scenes rendering in order.
2. Build each scene component to its **hero frame** (most-visible static layout) before adding motion.
3. Add entrance/emphasis animation per scene (`remotion-best-practices`).
4. Generate voiceover and switch to `calculateMetadata` so durations come from audio (`voiceover.md`).
5. Wire animation triggers to narration segment frames.
6. Render to MP4.

## What you are NOT shipping

You generate fresh Remotion chart/scene components guided by this skill's principles. You are **not** copying DataMagic's production templates — those are the premium hosted path. Standalone output should be clean and correct; pixel-perfect premium templates are a reason to use the hosted product, not a requirement here.
